# macOS and actual-game acceptance

Run these checks on macOS 14+ with Xcode and the actual selected Chrome game window. Record outcomes and exported logs. Do not mark unrun checks passed.

## Build and permission checks

- Run `swift test -j 2`. On macOS this includes `MacAdapterTests` and compiles the executable. Run `bash scripts/build-macos.sh`; verify an Apple Silicon `.app` is produced and its ad-hoc signature check passes.
- Launch the built app. Deny Screen Recording and verify an actionable error with no screenshot. Grant access, relaunch if requested, select the correct Chrome window and verify capture matches it.
- Confirm the window menu lists only browser windows with an active HTTPS open.mu document, including eligible windows on other Spaces. Other websites, a page merely titled open.mu, and an inactive open.mu tab must not be listed. Switch the selected browser to another website and verify capture/live input stops. Deny Accessibility and verify the URL-permission explanation appears. Restore the selected game before capturing/live automation. If enumeration fails, verify its native error domain/code appears; if it succeeds with no candidates, verify the empty-list explanation appears.
- Quit/relaunch Chrome with no screen reader running, open the game tab, then refresh Calibration. Verify the cold Accessibility tree populates and the game is listed. Repeat with several browser windows and while the game title changes during loading. Confirm per-window diagnostics explain exclusions; move identically positioned browser windows apart and refresh to resolve an ambiguous bounds match. A page containing only an open.mu link or iframe must stay excluded. Do not count these checks as passed based on the mocked tree tests.
- Test Retina scaling, resizing, window movement and browser zoom. Freeze preview, label regions, save/relaunch, and inspect alignment. Clear/recalibrate after layout changes.
- On macOS 26.0, switch Calibration → Dashboard at least 20 times using the navigation buttons, both with preview off and while preview is running. Also visit Workflows, Record route and Activity. Verify preview freezes when leaving Calibration, saved model edits/selected window/calibration survive navigation, Dashboard stays responsive, and the console does not flood with AttributeGraph cycle diagnostics. Repeat with Screen Recording denied and granted. This checks the native TabView reinsertion workaround against the supplied hang sample.
- Verify Accessibility is requested only through the live-input button. Revoke either permission during a workflow; verify subsequent input stops.
- Change Chrome tabs, close the target, select another Chrome window and focus another application. Verify no further action is delivered to the replacement target.
- Keep three Chrome game windows open with the same title and URL, give them distinguishable bounds, and select one in Calibration. Start and focus that exact window during the countdown. Verify a display-title difference/change does not require recalibration. Focus either other game window during a run and confirm no further input is sent. Switch/reload the selected tab (including another tab at the same URL when Chrome exposes a web-area identity) and confirm the run stops. Test route recording with the same window selection. These are native acceptance checks; mocked identity tests do not establish browser interoperability.
- Test Emergency Stop, its global chord, cancellation during countdown and waits, and closing the app window. Switching screens must not cancel a countdown or workflow; closing the owning app window must cancel it and stop preview/route recording. Closing an unrelated panel must not cancel it. Check no subsequent scheduled action fires. Already delivered events are outside cancellation control.

## Background sessions and timed refocus

- With Auto refocus and resume off, switch to another app and each of two other Chrome game windows during a macro. Confirm no new inputs elsewhere, Waiting for game focus appears, and returning to the exact selected game continues at the pending step with fresh evidence. Minimize/restore it and cover the next click point as well. The foreground app must never be activated automatically with this option off.
- Leave the game unfocused longer than an action/route/session timeout or a short macro hours limit. Confirm background time consumes none of those budgets and remaining recorded waits are retained. Confirm no repeated Transfer or other delivered press after focus returns. Switch during a key/mouse hold: release must occur, and the interrupted hold must not be replayed.
- Manually Pause while waiting, return to the game, and confirm it remains paused when Auto refocus is off. Resume must continue without restarting the macro. Changed tabs, reloads, revoked permissions, closed windows and changed layout must still stop for inspection.
- Enable Auto refocus and resume; test a short custom interval, then save/reload 30 minutes and 1 hour. With three same-title Chrome game windows open, switch to another app/window or minimize the selected game. Confirm the timer restores only the retained selected game, rechecks the original page/bounds and fresh OCR evidence, then continues without duplicating delivered inputs. Repeat from Manual Pause and idle full-mode monitoring. A long recorded wait must retain its timing, rather than being skipped by refocus. Count idle time from the last automation input, or from entering Pause/focus wait.
- Confirm temporary failed activation stays waiting and retries after the configured interval. Emergency Stop during a wait or refocus must prevent all future input/refocus attempts. Completed/failed/stopped sessions must never restart. Actual activation, Spaces behavior and input dispatch require macOS testing; portable tests simulate the adapter.

## Detection review

- In Calibration, verify all 44 target labels are grouped in workflow order and have descriptions. With Full automation selected and only banking enabled, verify the checklist requires 11 targets in relaxed recognition and 19 with Strict gameplay recognition enabled; switch the banking-proof option and verify the required proof changes. Enable Helper/recovery/skill evidence and verify their required targets appear. Select an existing target and verify its own OCR phrase and threshold load without changing the saved region. Label counts must not appear as proof of correct detection.
- Calibrate gameViewport to exclude browser chrome. Capture separate positive and negative examples for every required state/control.
- Load existing configuration and verify relaxed recognition defaults on while mode/module/key settings are preserved. With normalGameplay absent, verify a banking run uses the calibrated controls and finishes after verified transfer/panel closure. Enable Strict gameplay recognition and verify the same missing gameplay match blocks input. Verify configured interruption matches still stop input in both modes; switching recognition must not affect focus, permissions, Withdraw exclusion or Emergency Stop.
- Edit different existing targets to use different OCR phrases/thresholds, save, restart and reload. Verify each keeps its own settings without redrawing; switching to a new unlabeled target starts with an empty phrase. Change settings during Detect only and ensure stale results are discarded. Compare the selected crop against the stored template and per-target actual OCR/raw scores. Run the synthetic distinct-crop Vision test on macOS; Linux parsing does not validate Vision.
- With relaxed recognition, set a deliberately wrong optional OCR phrase on an image-backed panel and verify its saved image still matches; strict recognition must reject it. Numeric proof must still require readable OCR. Make a button template deliberately fail while keeping its correct saved rectangle, then verify the workflow clicks that rectangle in the selected window. Repeat for inventory open, bank open, transfer and both close controls. Strict mode must reject an unrecognized button. Momentary panel-detection misses may be polled, but a permanent missing bank or unverified success must time out with no second transfer or close click.
- Reject false bank matches against helper/warp/loading screens. Verify Withdraw is excluded and overlapping Transfer/Withdraw regions block Start.
- Verify helper settings and helper-running indicators are distinct. Verify normal gameplay, death, respawn, loading, disconnect, login and character selection are not conflated.
- Label actual death and respawn examples; combat effects and low health alone must not initiate recovery.
- Review Detect only output and scores with no input. Change any calibration/window selection and verify a new review is required.

## Click alignment

- Start with the physical pointer away from the inventory button. Run Dashboard's single inventory-click test, focus the selected game, and verify it clicks the saved button rather than the previous pointer location. Inspect before/after frames and the reported coordinates. This test must not open the bank or transfer jewels.
- Set a cursor position on `inventoryControl`, save/reload, and verify only that control's click location changes; its image/OCR/threshold and other targets must stay unchanged. Clear the override to restore the rectangle center. Test Retina/non-Retina displays and a display with negative global coordinates.
- Cover the intended point with another window during the pointer-settle interval; the press must stop. Cancel after mouse-down and verify mouse-up is still delivered so the button is not left held. Run `MouseInputTests` on macOS; injected event tests do not validate actual browser dispatch.
- Force an inventory-panel detection timeout. Confirm there is one click, no bank/transfer action, and the panel's raw score appears in the error and export. Frames must remain memory-only.

## Recorded jewel inputs and return route

- With no image labels, select a game window and record a jewel sequence. Wait for the start beep, click/key through the actual workflow with pauses, then release all controls and stop with Control–Option–Command–R. Verify that recording itself injects no input and excludes the stop chord.
- Save/restart and compare recorded positions, holds, waits, dimensions and purpose. Finish an empty or unsupported/incomplete recording and confirm the previous saved sequence is retained. Modifiers, drags and simultaneous controls must produce an explanation rather than a misleading recording.
- Replay from the same starting state and size with the physical pointer elsewhere. Confirm exact input order and correct targets. Confirm mouse/key release on cancellation or focus loss during a hold. A resized window must be rejected; moving the window between runs must preserve relative targeting.
- In recorded jewel mode, Start must not demand inventory/bank images or Detect only review. The final status must describe input playback completion and must not claim verified transfer success. Pause must stop future inputs, and death/disconnect evidence during a saved wait must prevent the next input.
- Record a return route. Configure positive/negative OCR examples for deathIndicator, deathConfirmation, respawnIndicator and destinationLandmark. In relaxed live detection, a saved matching image must not override an absent recovery OCR phrase. Test confirmed death → stable spawn → recorded inputs → verified destination without individual step image labels. Missing destination or route timeout must stop before Helper restarts.
- Set Macro repeats to 3 runs and confirm the complete sequence executes exactly three times, with no fourth cycle. Verify the first run is included, the optional between-run delay is honored, and Dashboard/Activity show completed counts. Save/reload and verify the repeat settings persist; old files must default to Once.
- Select hours, test expiration during a cycle and during a between-run delay, and confirm the current cycle finishes but no further cycle starts. Pause longer than the time budget, then resume; paused time must not consume hours. The default one-hour general session cutoff must not shorten an explicitly longer macro limit. Stop or a detected interruption must prevent subsequent cycles. Return-route replay must still execute once when macro repeats is enabled.
- Retest legacy image banking and checkpoint routes. Their saved settings and verification behavior must remain intact. Run the new native Vision/held-input tests; Linux tests cannot exercise the global event monitor or real browser input dispatch.

## Jewels only

- Begin with known eligible jewels and capture before-state evidence. Calibrate either a real new-success signal or a reliable numeric count/balance region. Select the matching verification mode and count format; verify OCR against known values. If no reliable signal exists, keep live banking blocked.
- With explicit live consent, start jewels-only mode. Verify inventory and bank open, Transfer is clicked once, Processing is treated as pending, success is verified, panels close and the run stops.
- Leave helper/recovery/skill switches enabled from full mode and repeat. Confirm none of those modules execute in jewels-only mode.
- Test zero eligible jewels, stalled Processing, an already visible success message, unexpected dialog closure and a missing Transfer button. Each ambiguous outcome must stop without a second transfer or a Withdraw click.

## Full routine

- Test helper inactive then already active. Confirm exactly one Start event for inactive and zero toggles for active; require the real running indicator.
- Configure actual verified key codes, order, delay and cooldown. Confirm sequences pause/stop with the workflow, do not run on unknown/death/disconnect states, and respect cooldown.
- Test calibrated banking trigger and cooldown without repeatedly opening inventory for polling. Validate empty-grid diagnostics against known counts; retain uncertain results as uncertain.
- Record the real return route. Assign each checkpoint and calibrate the destination. Run movement-only replay; verify it ends at the destination without starting helper. Make an edit and verify validation is cleared.
- Enable recovery only after verified route replay. Test false-positive death, confirmed death, verified respawn, respawn timeout, route failure, destination mismatch and disconnect during recovery.
- Confirm no helper restart on failed route/destination checks; confirm helper restarts and normal farming is verified after successful recovery.
- Test maximum session duration and recovery-count limits. Export the activity log and confirm action reasons, evidence and failure context are present.

Distribution signing/notarization is separate from these development acceptance checks and is not performed by the local ad-hoc build script.
